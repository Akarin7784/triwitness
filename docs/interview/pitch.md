# 讲稿（W8-08 草稿）

数字出处见 [README.md](README.md) 的速查表。终测（W8-01）数字已回填。

## 30 秒

我做了一个叫 TriWitness（三证）的编码 Agent：给它一个 GitHub Issue，它在沙箱里复现、修复、验证，最后交出一个带证据包的 PR 草稿。我的重点不是“让模型多写代码”，而是**让人能信它的结论**。实测里，只信 Agent 自己说“修好了”，有 28% 是假的；加上我做的确定性验证器，降到 15%，再加模型复核到 11%。整个项目只用一个便宜模型（DeepSeek Flash），每题几毛钱，所有数字都可复现。终测（test 35 题）完整流水线 54.3% vs 单 Executor 45.7%，方向一致但不显著（p = 0.25），而且贵一倍——这个我也会直接说。

## 2 分钟

**问题**：编码 Agent 最大的问题不是不会写，而是“自称修好了但其实没有”。我在 35 道近期真实仓库题上跑基线，48% 解决，但还有 6 次虚假成功——Agent 自信地说通过，隐藏测试不过。

**做法**：三件事。

1. **验证器**：干净沙箱复跑复现测试、只算新增失败的回归对比、7 条防作弊规则、再审计 Agent 的声明是否和它自己报告的风险矛盾。在 48 个历史补丁上，“可以直接信”的错误率从 28% 降到 15%，加模型判读到 11%，8 个已知假成功拦下 6 个。一个反直觉的发现：Agent 自己写的复现测试一个假成功都没拦住，因为它只证明“实现了它以为的需求”。
2. **用数据决定架构**：评审者变体在 40 道注入缺陷题上做消融，清单式非思考评审和对抗式思考评审检出率一样，但“没结论”从 20% 降到 7%，成本只有三分之一，所以默认用前者。在 dev 集上做 10 配置的单因素消融，开思考或加 Planner 解决率没变、成本 3 倍多——我如实写“dev 已饱和，只能看成本”。
3. **工程**：1M 上下文下按缓存价格设计压缩策略（命中价是未命中的 1/50），事件日志可续跑，外部副作用带幂等键，安全网关在 39 条红队用例上全部挡住。

**结果**：终测 test 35 题，完整流水线 54.3% vs 单 Executor 45.7%（+8.6pp，McNemar p = 0.25，不显著），同价成本约 2 倍；外部参照 Terminal-Bench 2.0 子集 28/30。

## 5 分钟（提纲）

1. **定位（30 s）**：Issue → 复现 → 修复 → 验证 → 评审 → PR 说明 + 证据包。v1 只在本地出分支和 PR 说明，开 PR 要人确认（没有做 GitHub App，这是有意收缩范围）。
2. **评测地基（1 min）**：从 SWE-rebench 挖题，Harbor 兼容目录，null=0 / oracle=1 ×3 校验；dev 15 / test 35 冻结、test 只出报告不调参；任务匿名 ID、清洗 Issue 里的提交链接防泄题。W2 基线 test 48%（33%–67%），新旧题差在 CI 内。失败主因是“探索太久撞 3M token 上限”，这直接推动了 repro-first 和上下文改造。
3. **验证器（1 min）**：三档数字（72% → 85% → 89% 精确率，召回 75% → 61% → 57%），说明我选择“牺牲召回换精确”——被拦下的真补丁落到 inconclusive 让人看，不会丢。讲清楚“模型看见风险却没降级”这个失败案例和后续规则修正（精确率 88%、错判 L3 归零）。
4. **多角色与消融（1 min）**：Planner / Executor / Verifier / Reviewer，状态迁移只由编排器做。评审者消融 + OFAT 两个结论；统计口径：配对 McNemar + Holm + 按题聚类 bootstrap，“区间不含 0 才写更好”。坦白小样本的可检出差异约 25–30 个百分点。
5. **成本与上下文（40 s）**：每题输入 214 万 token 但命中 97%，所以 ¥0.23/题；1M 工作预算、50% 清理到 25%、75% 才压缩。长上下文探针约 900K 召回全对。
6. **安全（30 s）**：出网白名单 + 凭证占位符（沙箱里没有真密钥）、MCP 工具指纹（“变脸”隔离）、参数级策略 fail closed；红队 39/39，关掉网关 35/39 得逞。说明这是确定性路径，真 Agent 端到端红队还没跑。
7. **终测与诚信（20 s）**：完整流水线 54.3%（38%–70%）vs 基线 45.7%（30%–62%），3:0 但 p = 0.25 不显著；同价成本约 2 倍、假成功 8/9 仍高——这些我都直接讲，全部数字注明日期、配置、模型快照、价格表版本，不和厂商自报分数比较。
