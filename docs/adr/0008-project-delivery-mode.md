# ADR-0008：项目交付模式（仓库改动 / 本地交付），创建项目时由用户选定

- 状态：**草稿**（2026-10-13，待蓝色大肥鱼审）
- 相关：ADR-0005（权限与沙箱模式）、ADR-0007（评审无结论不当通过）

## 背景

Eva 用三证生成「鹈鹕骑自行车」单文件 `index.html`，目的是拿到文件自己验证。工作流按 Issue → PR 走完，
交付的是一个 PR，而不是文件，交付物与用户目的不符（run `r_01M4RVEZWKASMK9HYES8RPTFK3`，
verdict `inconclusive`，原因是声明审计给出 `claim_flags: issue_underspecified`；复现脚本修复前失败、修复后通过）。

现状只有一种交付方式：工作树 → 验证 → 开 PR。对「给我一个能打开的文件」这类任务不合适。

## 决定

1. **模式由用户在创建项目时选定，与项目绑定**，不按任务描述推断。同一项目内不按任务切换。
2. 两种模式：
   - **仓库改动（默认）**：隔离工作树 → 改代码 → 验证 → 开 PR。三证核心卖点，保持不变。
   - **本地交付**：产出文件，验证后把产物拷到用户选定的目录，**默认不开 PR**。
3. **本地交付同样完整验证**：复现、测试、评审一步不少；结论卡照常给「通过 / 失败 / 无法判定」。
4. **本地交付也在隔离工作树里跑**，完成后再把产物拷到用户选的目录，不直接写用户文件夹。
5. **已有项目一律按「仓库改动」处理**；改绑入口第一版不做（见「后续」）。

## 考虑过的备选

| 方案 | 结论 | 理由 |
|---|---|---|
| 按任务描述推断模式（「生成 html / 给我文件」→ 本地交付；不确定时弹确认） | 否决 | 自动判断不合适，交付方式应由用户决定；推断错了会静默走错交付物 |
| 一律开 PR（现状） | 不满足 | 鹈鹕任务即反例：用户要文件，拿到的是 PR |

## 验收条件（合并标准）

- 创建项目页两个选项各配大白话说明，文案固定为：
  - 仓库改动：「改代码，验证后给你开 PR」
  - 本地交付：「生成文件，验证后放到你选的文件夹」
- 项目模式在**项目列表**和**任务页顶部**可见。
- 结论卡按钮随模式变：本地交付显示「打开文件」，仓库改动显示「查看 PR」。
- 阿验走查：两种项目各跑一遍，确认本地交付项目不开 PR、产物落在选定文件夹。

## 实现范围（仅方向）

- 项目元数据增加交付模式字段，缺省视为「仓库改动」。
- 编排收尾阶段按模式分支：开 PR，或把产物从工作树拷到用户选定目录。
- UI：创建项目页、项目列表、任务页顶部、结论卡按钮。
- 代码等 UI 第 2 批合并后再动。

## 后续

- 已有项目的模式改绑入口（需写清改完只影响之后的任务）。
- 本地交付项目中「顺便开 PR」的可选按钮，视使用情况再定。
