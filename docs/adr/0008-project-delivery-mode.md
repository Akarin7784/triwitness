# ADR-0008：交付模式两层决定——项目定默认，对话定本轮（仓库改动 / 本地交付）

- 状态：**已采纳**（2026-10-13，蓝色大肥鱼审过 `2dcfa67` 后通过）
- 相关：ADR-0005（权限与沙箱模式）、ADR-0007（评审无结论不当通过）

## 背景

Eva 用三证生成「鹈鹕骑自行车」单文件 `index.html`，目的是拿到文件自己验证。工作流按 Issue → PR 走完，
交付的是一个 PR，而不是文件，交付物与用户目的不符（run `r_01M4RVEZWKASMK9HYES8RPTFK3`，
verdict `inconclusive`，原因是声明审计给出 `claim_flags: issue_underspecified`；复现脚本修复前失败、修复后通过）。

现状只有一种交付方式：工作树 → 验证 → 开 PR。对「给我一个能打开的文件」这类任务不合适。

## 决定

两层都做，均由用户决定，不按任务描述推断。

1. **项目层（定默认）**：创建项目时二选一，决定该项目下对话的默认勾选。
   - 仓库改动 → 对话框默认勾选「开 PR」；
   - 本地交付 → 默认不勾。
2. **对话层（定本轮）**：对话框加「开 PR」勾选框，发起对话前可改。
   - 发出后本轮模式**锁定**，勾选框变成只读标签，并显示在对话顶部和侧栏对话条目上；
   - 要换模式只能新开一轮对话。
3. **两种模式**：
   - **勾选「开 PR」= 仓库改动**：隔离工作树 → 改代码 → 验证 → 开 PR。三证核心卖点，保持不变。
   - **不勾选 = 本地交付**：仍在隔离工作树中跑，完成后把产物拷到用户选定的目录，**不开 PR**，不直接写用户文件夹。
4. **两种模式同样完整验证**：复现、测试、评审一步不少；结论卡照常给「通过 / 失败 / 无法判定」。
5. **已有项目默认勾选「开 PR」**（视为仓库改动项目）；项目模式改绑入口第一版不做（见「后续」）。

## 考虑过的备选与理由

| 方案 | 结论 | 理由 |
|---|---|---|
| 按任务描述推断模式（不确定时弹确认） | 否决 | 自动判断不合适，交付方式应由用户决定；推断错了会静默走错交付物 |
| 一律开 PR（现状） | 不满足 | 鹈鹕任务即反例：用户要文件，拿到的是 PR |
| 只在项目层定模式 | 否决 | 同一项目里也会偶尔要「只给文件」或「顺便开 PR」，只能靠新建项目绕开，不顺手 |
| 只在对话层勾选、无项目默认 | 否决 | 每次都要想一遍，容易一路点默认又走错；项目默认让常用路径零操作 |
| **项目定默认 + 对话定本轮（采纳）** | 采纳 | 项目层给出符合该项目用途的默认值，对话层保留单次的灵活性；发出后锁定，保证一轮对话的交付物从头到尾一致，结论卡、按钮、标签不会半路对不上 |

## 验收条件（合并标准）

- 创建项目页两个选项各配大白话说明，文案固定为：
  - 仓库改动：「改代码，验证后给你开 PR」
  - 本地交付：「生成文件，验证后放到你选的文件夹」
- 对话框有「开 PR」勾选框，默认值跟项目模式一致，发起前可改。
- 发出后勾选框锁定为只读标签；对话顶部和侧栏对话条目都显示本轮模式标签。
- 项目模式在项目列表可见。
- 结论卡按钮跟**本轮**模式变：本地交付显示「打开文件」，仓库改动显示「查看 PR」。
- 阿验走查：两种项目各跑一遍，并在同一项目内各发一轮勾选 / 不勾选的对话；确认不勾选的轮次不开 PR、产物落在选定文件夹，发出后模式不可改。

## 实现范围（仅方向）

- 项目元数据增加默认交付模式字段，缺省视为「仓库改动」。
- 对话（run）记录本轮模式，发出后不可变；编排收尾阶段按本轮模式分支：开 PR，或把产物从工作树拷到用户选定目录。
- UI：创建项目页、项目列表、对话框勾选框、对话顶部与侧栏标签、结论卡按钮。
- 代码等 UI 第 2 批合并后再动。
